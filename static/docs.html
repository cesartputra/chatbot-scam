SIMULASI LOKAL · BUKAN API RESMI

Help Center OCR & Chat.

Satu input teks dan satu lampiran untuk percakapan lima tahap. Server menentukan urutan dokumen, mengirim patch field, dan membuat tiket dummy. Tidak ada pengiriman resmi, biometrik nyata, atau tindakan bank.

Alur percakapan

  1. Status pelapor → KTP → nomor HP dan email dalam satu jawaban.
  2. Bukti chat → lengkapi informasi terlapor → tambah bukti atau lanjut.
  3. Cerita serta waktu kejadian → laporan polisi berupa gambar atau lewati.
  4. Bukti rekening korban → transfer → tambah transfer atau lanjut.
  5. Ringkasan → jawaban CAPTCHA lokal menyatakan consent simulasi → tiket SIM-….

Field kosong/invalid dan confidence di bawah 0,85 menahan alur. Cerita memakai fakta pengguna; waktu yang belum disebut ditanyakan. Bukti tambahan menambah baris/transaksi. e-KYC tiruan bersifat opsional.

Upload menerima satu multipart file. Jenis diinferensikan dari expected_upload_type, bukan dipilih client. JPG/PNG/WebP maksimal 10 MiB dan 12 megapiksel, dibersihkan metadata dan dikompresi menjadi JPEG di bawah 900.000 byte. PDF/audio belum diterima.

POST .../chat
{"text":"Ya, saya sendiri"}

POST .../upload
multipart: file=@ktp-dummy.png

POST .../chat
{"text":"08123456789, pelapor.dummy@example.com"}

POST .../chat
{"text":"Lanjut ke Tahap 3","action":"continue"}

Quick reply memakai more_chat, more_transfer, skip_police, atau continue sesuai state. Koreksi API dapat memakai {"values":{"tahap1.email_pelapor":"koreksi@example.com"}}; perubahan membatalkan consent/tiket sebelumnya.

Pengisian progresif

{"state":"CONTACT_INPUT",
 "active_wizard_step":1,
 "expected_upload_type":null,
 "assistant_message":"Ketik nomor HP dan email Anda.",
 "dom_patches":[{"op":"set","path":"tahap1.nama_pelapor",
                 "value":"NAMA DUMMY","step":1}],
 "revision":2}

Setiap respons mutasi memuat patch leaf, langkah aktif, data, quick reply, dan revisi. File merupakan objek metadata atomik; tabel memakai path berindeks. GET sesi mengirim ulang seluruh patch untuk pemulihan.

Bridge replika memeriksa sumber/origin iframe, menerapkan field setiap 120 ms, menyorot/menggulir field, lalu berpindah ke tahap aktif. Radio, dropdown, tanggal, lampiran, dan tabel bersarang dipetakan. Isian manual dipertahankan; konflik diberitahukan. Sesi baru membersihkan isian AI sebelumnya sambil mempertahankan edit manual.

Tiket dan adapter lokal

Pada FINAL_CONFIRMATION, pesan menjelaskan consent S&K simulasi. Pengguna mengetik jawaban CAPTCHA ke /chat; jawaban benar membuat tiket di chat/host. Widget tidak menghitung atau mengirim jawabannya otomatis. Maksimal lima jawaban salah.

POST .../submit
{"setuju_syarat_dan_ketentuan":true,
 "captcha_answer":"jawaban pengguna",
 "integration_mode":"dom"}

Adapter eksplisit dom mengembalikan mapping replika; webhook memanggil mock lokal. URL webhook eksternal/resmi ditolak. Hasil selalu SIM-…, SIMULATED_NO_BANK_ACTION, submitted:false; tidak ada ring-fencing/tracing.

Embedding, konfigurasi, dan batas

<script src="http://127.0.0.1:8787/static/widget.js" defer></script>

API dipanggil iframe ke origin intake yang sama. Atur EMBED_ORIGINS serta CSP host. Bridge data-integrate="replica" hanya aktif pada origin yang sama; integrasi ASP.NET resmi masih membutuhkan kontrak field/master ID, modal, file, dan autentikasi dari pemilik portal.

Provider utama chat: Sumopod AI melalui API OpenAI-compatible resmi. Key hanya disimpan pada server. Pilih model yang tersedia pada dashboard atau /v1/models untuk key Anda; daftar dapat berbeda antar akun.

AI_MODE=auto
AI_BASE_URL=https://ai.sumopod.com/v1
AI_API_KEY=isi_key_sumopod_di_server
VISION_INPUT_MODE=image
VISION_MODEL_NAME=gemini/gemini-3.5-flash-lite
CHAT_MODEL_NAME=deepseek-v4-flash
AI_RESPONSE_FORMAT=json_object

Key kosong memakai simulasi bukti non-KTP berlabel. Isi key lalu restart untuk mengaktifkan Sumopod. Satu key dapat dipakai untuk kedua model bila izinnya tersedia. Ekstraksi JSON teks dan vision berhasil pada uji live dummy; semua balasan asisten tetap berupa template Python. Dengan ocr_text, hanya teks OCR yang telah dimasking dikirim ke model ekstraksi teks.

Instal Tesseract dan trained data eng: macOS brew install tesseract; Debian/Ubuntu sudo apt-get install tesseract-ocr tesseract-ocr-eng. KTP selalu diproses lokal, termasuk pada simulasi, dan ditolak gateway LLM. Bukti lain wajib lolos pemeriksaan OCR lokal terhadap KTP, injeksi, dan relevansi sebelum API. Gambar tidak terbaca ditolak; foto buram membutuhkan koreksi. Masking teks tidak mengubah piksel gambar: gunakan bukti dummy atau yang sudah disamarkan.

Aturan dapat diperbarui di services/guardrails.py: hanya empat tugas ekstraksi laporan/bukti diizinkan. Input maksimal 2.000 karakter; prompt injection dan topik di luar pelaporan mendapat penolakan tetap tanpa API atau perubahan draft. Kontak, koreksi pribadi, dan kronologi diproses lokal. LLM dikunci pada temperature=0 dan JSON object dengan flag relevansi/injeksi. Field asing, teks balasan bebas, dan nilai tanpa dukungan sumber ditolak. OCR/pola bukan jaminan kebal seluruh injeksi atau bukti asli; tinjau hasil sebelum melanjutkan.

Gateway tetap model-agnostic. Alternatif on-premise: AI_MODE=remote, VISION_INPUT_MODE=image, AI_BASE_URL=http://127.0.0.1:4000/v1, serta alias Qwen vision/DeepSeek chat pada satu gateway OpenAI-compatible. Mode image mengirim gambar langsung dan memerlukan model yang benar-benar mendukung input gambar. HTTP tanpa TLS/keyless hanya untuk localhost; on-premise belum diuji.

Satu worker, sesi/file di memori, maksimal 20 sesi, masa tidak aktif satu jam, dan 12 unggahan per sesi. Restart menghapus sesi. Token memberi akses data/file; perlakukan sebagai rahasia. Katalog lokasi/bank masih demo, verifikasi perwakilan/surat kuasa belum tersedia. PoC belum untuk data pribadi nyata atau akses publik.
